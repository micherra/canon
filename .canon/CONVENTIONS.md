## Project Conventions

> Project-specific patterns and decisions. Auto-detected by init and refined as the project evolves.
> Engineer agents read this file alongside Canon principles.

- **Language**: TypeScript (ES modules) with Node.js 25.x (pinned to 25.8.0 in .tool-versions)
- **Naming**: camelCase for functions and variables, PascalCase for types and interfaces
- **Functions**: Prefer arrow functions (`const foo = () => {}`) over function declarations; exception: exported functions that need hoisting
- **File naming**: kebab-case for files and directories
- **Module structure**: Feature-based directories under `features/` (e.g., `knowledge-graph/`, `orchestration/`, `file-context/`), each with `tools/`, `services/`, and `__tests__/` subdirectories. One tool per file in `tools/`.
- **Schema validation**: Zod schemas at API/tool boundaries
- **Testing**: Vitest with co-located `__tests__/` directories
- **Error handling**: Tool functions return `ToolResult<T>` (from `utils/tool-result.ts`) for expected errors — no throwing; unexpected errors caught by `wrapHandler` and returned as `UNEXPECTED` `CanonToolError`; `utils/errors.ts` for internal path/file utilities
- **Data persistence**: JSONL files in `.canon/` with atomic writes for reviews/drift; SQLite KG (`knowledge-graph.db`) via `KgQuery`/`KgStore` is the primary store for graph and summary data (ADR-005); no JSON artifacts are written for graph or summary data.
- **Imports**: Explicit `.ts` extensions for TypeScript ES module imports (matching Vitest/tsx execution)
- **Frontend**: Self-contained HTML artifacts generated by renderer agents; Canvas/SVG for graph rendering; design system tokens in `mcp-server/src/ui/snippets/DESIGN-SYSTEM.md`
- **Enrichment tier**: Always read session tier from `getExecutionStore(workspace).getSession()?.tier ?? "medium"`.
- **Criteria Coverage table**: All implementation logs must include a populated `#### Criteria Coverage` table mapping every task-plan acceptance criterion to what was implemented. Use disposition vocabulary: `covered` (fully addressed), `descoped` (intentionally omitted with rationale), `partial` (addressed in part — state what remains). A missing or empty table is a summary defect; the reviewer flags it in Stage 3.
- **Learning log triage cadence**: Learning log suggestions are triaged every 5 soak runs. Suggestions older than 5 runs that remain unactioned are either applied, deferred with rationale, or closed as stale.
- **No `for...of await` in plan pseudocode**: Architect task plans must use `Promise.all` (or `Promise.allSettled`) for concurrent async operations, never sequential `for...of await` loops. Biome's `noAwaitInLoops` rule catches this at verify, but the engineer implements plan pseudocode verbatim — encoding the anti-pattern in the plan guarantees a verify failure. 2/2 plans with sequential-await pseudocode produced lint failures.
- **Rule file taxonomy registration**: When creating a new rule file in `principles/rules/`, the author must register it in `rules/.claude/CLAUDE.md` taxonomy table. 2/2 new rule builds missed this and were caught only at review (BLOCKING).
- **Large-file line-count risk check**: Task plans targeting files with `hotspot_score > 0.7` or known large files must check the current line count against Biome's `noExcessiveLinesPerFile` limit (600 lines). If the file is near the limit, the plan must include an extraction strategy. 2/2 builds that skipped this required emergency file splits at verify.
- **Team review dispatch for large diffs**: Single-reviewer dispatch must not be used for diffs exceeding 40 files OR 5,000 lines. Use team review dispatch (Phase 1–3) for large diffs to prevent reviewer context exhaustion. 1/1 large-diff single-reviewer spawns failed without producing a review artifact.
- **Scribe pre-classification for large builds**: For builds touching 20+ files, the orchestrator must provide a pre-classified bullet-list change summary in the scribe spawn prompt. Without pre-classification, the scribe attempts to read the full diff and context-exhausts. 1/1 large-diff scribe spawns without pre-classification failed; re-spawn with summary succeeded.
- **Mechanical enforcement over behavioral instructions**: Required post-step behaviors (transcript capture, artifact scanning, metric recording) must be implemented as mechanical side-effects in the executing code (e.g., logStep calling captureTranscript internally), not as instruction-list items in CLAUDE.md Post-Step Effects. Passive instruction lists have demonstrated 0% reliability for required behaviors. 2/2 NF fixes confirmed: moving the obligation into code resolved the failure permanently.
- **Intentional bare-catch with comment**: Bare `catch {}` blocks are permitted when accompanied by a short explanatory comment stating why the error is intentionally ignored (e.g., `/* ignore close errors */`, `// Fall through`, `// Fail-open`). A bare catch without a comment is a silent swallow and should be flagged. 144 instances in production follow this pattern consistently.
- **MCP batch tool pattern**: When an MCP tool is called N times in a loop with independent inputs, create a batch variant. Batch tools follow a standard shape: accept an array input, perform a single I/O operation (one DB query, one file scan), apply fail-closed validation on each input, and return early on empty arrays. Use a batch tool when callers have all inputs upfront and need reduced round-trips. Use a composite tool (like `get_context`) when callers need orchestrated multi-source lookups with conditional logic. 4/4 batch tools (`getPrinciplesBatch`, `getFileContextBatch`, `get_context`, `batch_log_steps`) follow this pattern.
- **Prefer agent-targeting fixes over orchestrator-targeting fixes**: When a behavioral failure can be fixed by modifying either orchestrator instructions (CLAUDE.md) or agent instructions (agent rules/frontmatter), prefer the agent-targeting fix. Agent-targeting fixes are self-validating — the fixed agent runs in the same build cycle and proves the fix works. Orchestrator-targeting fixes cannot be validated until a future build exercises the changed behavior.
- **Verify engineer baseline-check protocol**: Before reporting verify results, the engineer diffs the worktree branch against main to identify pre-existing failures. Pre-existing lint/build/test errors are reported separately from new errors introduced by the build. Pre-existing errors in files the engineer touched are fixed opportunistically under "leave touched files better." Confirmed across 4/4 eligible verify scenarios.
- **DAG wave file-assignment before wave**: When producing a task DAG for parallel execution, assign tasks to files first, then assign to waves. Tasks sharing a file must be in different waves with a `depends_on` edge. This prevents merge conflicts at wave boundaries. Confirmed across 3/3 parallel-safe builds with 0 merge conflicts.
- **Agent permissionMode-write-tool coherence**: Adding write tools (`Write`, `Edit`, MCP write tools) to an agent's `tools:` frontmatter requires checking that the agent's `permissionMode` allows write operations. Agents in `plan` or read-only modes must not receive write tools. The architect/engineer must verify this alignment when modifying agent definitions.
- **Agent instruction-tools-list coherence**: When modifying agent instruction documents (`agents/*.md`) to reference MCP tool calls (e.g., `mcp__canon__*`), the `tools:` frontmatter list must be updated to include those tools. Verification: grep the agent doc for `mcp__canon__` identifiers and cross-check against frontmatter. 2/2 builds that missed this were caught as BLOCKING at review.
- **Drift/history adapters delegate decay to the shared confidence engine**: Adapters in `platform/storage/drift/` that compute a domain confidence signal (e.g., doc freshness, drift confidence, watch staleness) must compose their signal(s) and call `computeConfidenceAnnotation` from `@shared/lib/confidence.ts`. Do not write a second decay/scoring function — the weighting and tiering logic is owned by the shared kernel. Re-export `ConfidenceAnnotation` from the adapter as a bounded-context boundary so callers do not import directly from `shared/lib`. Confirmed across 3/3 adapters: `drift-confidence-adapter.ts`, `doc-freshness-adapter.ts`, `watch-staleness-adapter.ts` (3rd instance, promoted to convention 2026-06-04).
