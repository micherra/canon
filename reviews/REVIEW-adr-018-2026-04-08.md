**Note on security scan finding**: The security scan flagged `validateRequiredHandoffs` in `report-result.ts` for using `isPathContained` without `isPathInWorktree`. Reviewing the code: `validateRequiredHandoffs` at line 238 constructs `metaPath` as `join(workspace, "handoffs", "${req.name}.meta.json")` where `req.name` is validated by `RequiredArtifactSchema` regex `/^(?!\.{1,2}$)[A-Za-z0-9._-]+$/` — this regex prevents path separators and `..` traversal. The path is deterministically constructed from a schema-validated name within a trusted workspace. `isPathContained` is appropriate here; `isPathInWorktree` is not needed. **No violation.**

- **information-hiding**: The handoff format decision (`.md` files + `.meta.json` sidecars in `handoffs/`) is encapsulated in the write tools and injection/validation code. Consumers interact through the `ContextInjection` abstraction (`from: "handoff"`) rather than knowing the directory layout.

### Code Quality (Advisory)

#### Suggestions

- **Missing tool-profiles entries (WARNING)**: `write_research_synthesis` is listed in `researcher.md` frontmatter but absent from `AGENT_TOOL_PROFILES["researcher"].allowed` in `tool-profiles.ts`. Similarly, `write_design_brief` is listed in `architect.md` but absent from `AGENT_TOOL_PROFILES["architect"].allowed`. The tool-profiles system (ADR-014) is the enforcement layer — the frontmatter list alone does not grant tool access at runtime. Agents will be unable to call these tools. **Fix**: Add `"write_research_synthesis"` to the researcher profile and `"write_design_brief"` to the architect profile in `tool-profiles.ts`.
- **No `escapeDollarBrace` on handoff injection output**: The `resolveHandoffInjection` function returns raw file content. The CONVENTIONS.md entry for KG context formatting states "The formatter returns raw unescaped text; callers apply `escapeDollarBrace()` at their own trust boundary." Handoff markdown could contain `${...}` sequences that would be interpreted as variable references by the orchestrator's variable substitution. Verify that the caller (`drive-flow.ts` or equivalent) applies escaping to handoff injection variables, or add escaping in `resolveHandoffInjection` before returning. Low risk in practice (handoff content is agent-generated), but worth verifying.
- **50KB cap continues checking after skip — untested edge case**: The plan specifies that after skipping a file that exceeds the cap, remaining smaller files should still be checked and included. The code implements this correctly (line 239: `continue` after skip), but the test suite only tests the skip warning, not the "smaller file fits after large skip" path. Consider adding a test.
