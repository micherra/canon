## Task: v2.1b loop-closure evidence (substrate proof)

### Action

Produce the **v2.1b loop-closure evidence**: ≥ 1 principle-refinement proposal generated by the learner against real v2.1b-era lifecycle data, accepted by a human reviewer, and applied as an actual edit to a principle file. The full observation → pattern → proposal → refinement loop must close.

> **Name disambiguation.** v2.md §15.2 defines Gate B as a process check runnable *today* against the pre-v2.1b drift-db schema (a ~30-line SQL script producing one finding-count-per-principle analysis). That Gate B is a ratification-gate for v2.1 *as a whole* — it proves the loop CAN run, not that v2.1b's substrate works. This task produces a different, stronger artifact: **loop-closure evidence against v2.1b-era data** — a round-trip through the substrate built in v2_1b-00..06. Both are needed, at different moments; they are not the same milestone.

**This is a measurement + curation + application task, not a code task.** The outcome IS the evidence that the v2.1b substrate works.

**Procedure:**

1. **Prerequisites:**
   - v2_1b-00 through v2_1b-06 all shipped
   - At least 20 completed flows since v2.1a shipment (per v2.1b entry gate)
   - Each flow has: a lifecycle snapshot row (v2_1b-01); review findings with `principle_id` populated (v2_1b-05); any fix summaries with `cause` + `root_cause_tag` (v2_1b-03); any implementation summaries with `justified_deviations[]` (v2_1b-04)

2. **Run the learner** against the accumulated data:
   - Invoke `learner` in analysis mode (the new principle-refinement dimension from v2_1b-06)
   - Output: `.canon/proposed-learnings/{timestamp}/` containing one or more principle-refinement proposals

3. **Human curation (weekly review per §3.4):**
   - Canon maintainer reads each proposal
   - For at least one proposal: accept + apply
     - Apply = edit the relevant `principles/{category}/{name}.md` file with the proposed patch (or a refined version — the curator may edit the patch before applying)
     - Commit the principle edit with a clear message citing the proposal ID
     - Record the decision in `.canon/learning.jsonl` (existing Canon convention)
   - Rejected / dismissed proposals are also recorded in `.canon/learning.jsonl` so the learner avoids re-proposing

4. **Document the evidence** at `docs/v2.1b-loop-closure-evidence.md`:
   - Analysis invocation details (date, flow count, tool versions)
   - Proposal list (at least one accepted)
   - For the accepted proposal: the original proposal text, the curator's decision rationale, the actual edit applied, the principle diff
   - The learning.jsonl record
   - Explicit statement: "v2.1b loop-closure evidence met. Observation → pattern → proposal → refinement loop closed for principle refinement against v2.1b-era data."

### Canon principles to apply

- **agent-evidence-over-intuition** — this task IS evidence production; every claim must be traceable to a specific flow, snapshot, finding, or proposal
- **agent-design-before-code** — the accepted proposal's patch was designed against the substrate; no arbitrary principle edits

### Risk mitigations

- Learner expands write scope too aggressively (§13 MEDIUM/LOW): curator is the human gate — no automation applies proposals
- Observation tag compliance (§13 LOW/LOW): if Gate B fails because tags are inconsistently populated, the fix is backfill / re-run, NOT lowering the bar
- **Review MEDIUM-1 (v2.2 entry gate is volume-based):** Gate B here is volume-gated. The quality criterion (accepted proposal produces measurable reduction in principle violation rate over next N flows) is tracked by v2.2's entry gate, not Gate B. Note this explicitly in the evidence doc so v2.2 planners remember.

### Tests to write

No unit tests. The evidence doc IS the test output. If the substrate does not produce an acceptable proposal in reasonable time, Gate B fails — v2.1b does not ship to ratification.

### Verify

1. `docs/v2.1b-loop-closure-evidence.md` exists with all required sections
2. At least one proposal in `.canon/proposed-learnings/{timestamp}/` is cited
3. At least one `principles/*.md` diff (applied refinement) is cited
4. `.canon/learning.jsonl` has the decision record
5. The principle edit is in main (committed)
6. Evidence doc cross-referenced from `docs/agent-teams-migration-plan-v2.md` §10.3 v2.1b exit criteria

### Done when

- Evidence doc committed
- Principle edit committed
- `.canon/learning.jsonl` updated
- Loop-closure explicitly declared met in the evidence doc
- If loop-closure FAILS (no credible proposal produced, or curator rejects all): task is BLOCKED; diagnose (insufficient data? learner bug? tag population gap?) and file a remediation task before retrying
