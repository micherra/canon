Review proposed learnings generated by Canon's auto-triggered learning system (ADR-016). Each proposal suggests a principle or convention change based on patterns observed in recent flows.

## Instructions

### Step 1: Discover proposals

Glob for proposal directories: `.canon/proposed-learnings/*/`

If no directories exist, tell the user:
"No pending proposals. Canon will generate proposals automatically after enough flows complete (default: 5 flows, 48 hours since last analysis)."
Stop here.

Sort directories by timestamp (newest first). If `--all` is passed, show all proposals. Otherwise (default or `--pending`), only show proposals that have not been acted on yet. A proposal directory has been acted on if it contains an `applied/`, `rejected/`, or `dismissed/` subdirectory with at least one file inside.

### Step 2: Present proposals

For each proposal directory, read all `.md` files within it (excluding any files inside `applied/`, `rejected/`, or `dismissed/` subdirectories). Parse the YAML frontmatter for `proposal_id`, `type`, `confidence`, and `target`.

If a target principle or convention referenced by a proposal no longer exists in its expected location, inform the user and skip the proposal:
"Proposal {proposal_id} references {target} which no longer exists. Skipping."

Present a summary table:

```
## Proposed Learnings ({count} proposals)

| # | Type | Target | Confidence | Observation (first line) |
|---|------|--------|------------|------------------------|
| 1 | new-convention | — | 0.85 | Error boundaries missing in 8/12 API handlers |
| 2 | severity-change | no-silent-failures | 0.72 | 15 violations in last 10 reviews suggest promotion |
```

Then for each proposal, show the full content and ask:

**"Accept / Reject / Dismiss / Skip?"**

- **Accept**: Apply the proposed change
- **Reject**: Remove this proposal (with reason logged)
- **Dismiss**: Permanently suppress — the learner will not re-suggest this pattern
- **Skip**: Leave for later review

For any proposal that would demote a rule-severity principle, show an extra confirmation step before accepting:
"WARNING: This proposal demotes a rule-severity principle. Rules are the strongest constraints in Canon. Are you sure you want to proceed? (yes/no)"
If the principle is tagged as security-related, refuse the demotion entirely:
"Demotion of security-tagged rules is not permitted. Rejecting this proposal."

### Step 3: Apply accepted proposals

Based on the user's choice:

| Proposal type | Apply action |
|--------------|-------------|
| new-convention | Append to `.canon/CONVENTIONS.md` |
| severity-change | Edit the principle's YAML frontmatter severity field and move file to the appropriate subdirectory |
| principle-revision | Read the principle file, apply the proposed change to the relevant section |
| convention-graduation | Tell the user to run `ask Canon to create a new principle {topic}` — canon-writer handles interactive authoring |
| stale-removal | Remove the convention line from `.canon/CONVENTIONS.md` |

If an apply action fails (file not found, write error, etc.), report a clear error message and do not silently skip:
"Failed to apply proposal {proposal_id}: {reason}. Leaving proposal in place."

After applying:
1. Move the proposal file to `.canon/proposed-learnings/{timestamp}/applied/` (create subdirectory if needed)
2. Append an entry to `.canon/learning.jsonl`:
   ```json
   {"timestamp":"...","proposal_id":"...","action":"accepted","type":"...","target":"..."}
   ```

For rejected proposals:
1. Ask the user for a reason (brief, optional — press Enter to skip)
2. Move to `.canon/proposed-learnings/{timestamp}/rejected/`
3. Append: `{"timestamp":"...","proposal_id":"...","action":"rejected","reason":"..."}`

For dismissed proposals:
1. Move to `.canon/proposed-learnings/{timestamp}/dismissed/`
2. Append: `{"timestamp":"...","proposal_id":"...","action":"dismissed"}`

For skipped proposals:
- Leave the proposal file in place; do not append to `learning.jsonl`

### Step 4: Summary

After processing all proposals:
```
Accepted: N | Rejected: M | Dismissed: K | Skipped: L
```

If any proposals were accepted, suggest the user run `/canon:check` to verify the changes.

### Constraints

- Only modifies files the user explicitly approves
- Proposal files are moved (not deleted) to preserve audit trail
- `learning.jsonl` is append-only
- Never demote security-tagged rules; show extra confirmation for any rule demotion
- If a target principle or convention no longer exists, inform the user and skip rather than failing silently
